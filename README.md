# وصلة كهرباء (Wasla Kahraba)

تطبيق ويب مدعوم بالذكاء الاصطناعي يساعد الناس على معرفة أماكن شحن الهواتف
والأجهزة الصغيرة المتاحة حاليًا، بدل السؤال المباشر أو البحث بمجموعات
التواصل. راجعي `wasla-kahraba-design-doc.md` لتفاصيل التصميم الكاملة.

## التشغيل

```bash
pip install -r requirements.txt
cp .env.example .env   # اختياري — شغالة بدون مفتاح عبر fallback
python app.py
```

افتحي المتصفح على `http://localhost:8080`

- **صفحة البحث** (`/`) — للمستخدم العام، بدون تسجيل دخول
- **لوحة أصحاب النقاط** (`/owner`) — تسجيل حساب جديد أو دخول بمفتاح موجود

## بيانات تجريبية جاهزة

عند أول تشغيل، تُحمَّل تلقائيًا:
- مالكين تجريبيين بمفاتيح دخول: `demo-owner-key-001` (مركز المجتمع، عنده
  نقطتين)، `demo-owner-key-002` (جمعية الشباب، عندها نقطتين)
- 4 نقاط شحن بحالات وتواريخ متنوعة (بعضها حديث، بعضها "قديم" عمدًا
  لاختبار Freshness Indicator)

## بنية المشروع

```
flask_app/
├── database/
│   ├── create_tables/     ملفات SQL لكل جدول
│   └── initial_data/      بيانات تجريبية (CSV)
├── templates/              صفحات HTML (Jinja2)
├── static/css, static/js   التصميم والتفاعل
├── utils/
│   ├── database.py        كل التعامل مع قاعدة البيانات
│   ├── llm.py              طبقة الـ LLM Agent (بدون exec() على كود مولّد)
│   └── embeddings.py       توليد الـ embeddings للبحث الدلالي
└── routes.py                مسارات الـ URL
```

## قرارات تصميم مهمة (وليش)

- **بدون طبقة اعتماد مسؤول**: تحديثات صاحب النقطة تظهر فورًا بدون مراجعة
  بشرية. التعويض: Freshness Indicator يحذّر لما المعلومة تصير أقدم من
  24 ساعة.
- **owner_key يتحقق مرة وحدة بتسجيل الدخول** (session)، مو بكل تحديث.
- **لا exec() على كود الـ LLM**: كل خبير يرجع نص عادي أو JSON يُتحقق منه
  بكود بايثون ثابت قبل ما يلمس قاعدة البيانات.
- **مالك واحد ممكن يمتلك أكتر من نقطة**: جدول `owners` منفصل عن
  `charging_points` (علاقة واحد لكثير).
